# Сравнение с Go (спец для ВШЭ)

Краткая шпаргалка: как темы семинара 3 (лямбды, генерики, Optional и т.д.) выглядят в Java и как они решены в Go.
Go — не функциональный язык, поэтому сравнение наглядно показывает, *что* в Java является «фичами», а *что* — лишь
обёрткой над императивностью.

---

## Функции и лямбды

В Go функции — значения первого класса **по природе** (как в JS), без интерфейсов-обёрток. Лямбда (анонимная функция)
существует сама по себе и присваивается переменной любого функционального типа.

```go
// Go: функция — самостоятельное значение, тип = сигнатура
double := func(x int) int { return x * 2 }   // анонимная функция

// передача как аргумент
twice := func(fn func(int) int, v int) int { return fn(fn(v)) }
twice(double, 3)   // 12
```

```java
// Java: лямбда обязана реализовать функциональный интерфейс
Function<Integer, Integer> double_ = x -> x * 2;
twice(double_, 3);
```

**Вывод:** в Go функции первоклассны, как в JS; в Java — имитация через функциональные интерфейсы.

## Генерики

В Go генерики появились **поздно** (Go 1.18, 2022) и до сих пор ограничены: нет wildcard и вариативности типов.
Вместо `? extends T` / `? super T` — интерфейсы как границы (constraints), а PECS не нужен, потому что нет ковариантности
и «in/out» проверок на уровне типа.

```go
// Go: constraint — интерфейс с методом
func TopByTicker[T InstrumentLike](list []T) T { ... }
```

```java
// Java: bounded type + wildcard
<T extends Instrument> T topByTicker(List<T> list) { ... }
List<? super T> dest;
```

**Вывод:** обе идеи «тип как параметр» есть, но Java богаче (bounded + wildcard + PECS), а Go — проще и строже
(только constraints, никаких ковариантных подставлений).

## Optional и `null`

В Go **нет** `Optional` и **нет** `null`-безопасных обёрток. Отсутствие значения выражается либо:

- указателем (`nil`), но `nil` разыменовывать нельзя — надо проверять;
- или типом с явным признаком (часто `value, ok` возвратом из функций).

```go
// Go: value, ok — пара из функции
v, ok := m["key"]
if !ok {
    // нет значения
}
```

```java
// Java: Optional как обёртка «есть / нет»
Optional<String> v = Optional.ofNullable(map.get("key"));
String res = v.orElse("default");
```

**Вывод:** Java инкапсулирует опциональность в тип (`Optional`), Go — в **явный возврат пары** и проверку. В Go нет
«магического» пропуска `null` — компилятор не даёт разыменовать `nil` без проверки.

## Ошибки: try-catch vs error

Здесь главный философский контраст.

```go
// Go: ошибка — обычное значение, проверяется вручную
f, err := os.Open("file.txt")
if err != nil {
    return err   // ошибка «течёт» явно через return
}
```

```java
// Java: ошибка — исключение, летит вверх по стеку
// Vavr: ошибка становится значением (Try/Either) — ближе к Go
Try<File> f = Try.of(() -> new FileInputStream("file.txt"));
f.onFailure(System.err::println);
```

**Вывод:** Go и Vavr сходятся — ошибка как **значение**, а не скрытый поток управления. Но в Go это природа языка
(нет исключений вообще), а в Java — либо исключения, либо библиотека Vavr поверх них.

## Неизменяемость и Stream

- В Go **нет** неизменяемых коллекций по построению и **нет** аналога `Stream`. Есть функции `map`/`filter` вручную,
  но срезы (slices) мутабельны.
- Идиоматичный Go — явные циклы `for range`, мутация — норма.

```go
// Go: циклы и мутация — норма
var upper []string
for _, w := range words {
    upper = append(upper, strings.ToUpper(w))   // новый срез, но вручную
}
```

```java
// Java: Stream — декларативно, лениво
List<String> upper = words.stream().map(String::toUpperCase).toList();
```

**Вывод:** Java (через Stream) ближе к ФП, чем Go. Go — намеренно простой и императивный, «ФП» там ограничено
функциями первого класса.

## Итоговая таблица

| Тема | Java | Go |
|---|---|---|
| Функции как значения | через функциональные интерфейсы (имитация) | да, по природе (как JS) |
| Лямбда | `Function<T,R>` и т.п. | анонимная функция `func(x int) int` |
| Генерики | bounded + wildcard + PECS | constraints (интерфейсы), с 1.18 |
| Optional | `Optional<T>` | `value, ok` / проверка `nil` |
| Ошибки | исключения (+ Vavr Try/Either) | `error` как возвращаемое значение |
| Неизменяемость | `final`/`List.of`/`toList()` | нет по построению, мутация — норма |
| Stream / map-filter | `Stream API` (ленивый) | ручные циклы `for range` |
| Композиция функций | `andThen`, `compose`, `Predicate.and` | вложенные вызовы функций |

---

## Главный тезис

- **Java** подходит к ФП «через надстройки»: Stream, Optional, Vavr, лямбды как интерфейсы — всё это добавлено поверх
  императивно-объектного ядра.
- **Go** проще: берёт из ФП только **функции первого класса**, а всё остальное решает императивно — явные циклы,
  ошибка как значение, `value, ok`. Никаких обёрток и «имитаций» — но и меньше выразительности.
