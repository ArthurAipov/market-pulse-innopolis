# Требования к файловому хранилищу котировок

Самостоятельная работа к семинару 7 (см. «План семинара.md», раздел «Взаимодействие с файловой
системой» — вне тайминга занятия, на занятии или дома). Эталонная реализация существует
(`persistence/QuoteFileStoreReference.java` и далее) — для разбора в начале семинара 8 при
необходимости, не как единственно верный ответ.

## Контракт

Интерфейс `academy.backend.market_pulse.persistence.QuoteFileStore`:

```java
void save(Path path, List<Quote> quotes);
List<Quote> load(Path path);
```

Формат файла не навязывается. Обязательно:

1. `load(save(path, quotes))` возвращает те же котировки (тикер, тип, название, валюта, цена,
   изменение за период).
2. Если файла ещё нет — `load` возвращает пустой список, а не бросает исключение.

## Что должно получиться вокруг контракта

- **Команда `update`** — через `TInvestApiClient` (см. этапы 2/6) забирает актуальные котировки для
  тикеров из `Watchlist`, формирует новый файл с обновлёнными значениями через `QuoteFileStore`.
- **`FileBackedQuoteRepository`** — читает файл один раз и держит результат в памяти (кеш), не
  перечитывает на каждый запрос.
- **`QuoteFileWatcher`** (`WatchService`) — отслеживает изменение файла на диске и инвалидирует кеш
  `FileBackedQuoteRepository`, чтобы следующее обращение перечитало актуальные данные.

## Не требуется

- Поддержка конкурентного доступа к файлу из нескольких процессов.
- Миграция формата файла между версиями.
- Интеграция с `MappedByteBuffer` (это отдельная тема, см. ниже в «План семинара.md» — для больших
  файлов, не для обычного размера файла с котировками watchlist).
