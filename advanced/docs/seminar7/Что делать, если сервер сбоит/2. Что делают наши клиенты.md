# 2. Что делают наши клиенты

Эксперимент: сервер на `localhost:1080`, оба клиента с настройками `TInvestApiProperties.localMock()`
(connect 2 с, request 5 с). Реальные результаты:

| Сервер | `HttpClientTInvestApiClient` | `ReactorTInvestApiClient` |
|---|---|---|
| Отвечает `500` сразу | `TInvestApiException`: «неожиданный статус: 500», 45 мс | `TInvestApiException`, 4 мс |
| Отвечает `200` через **8 с** | `TInvestApiException` по таймауту, **5 007 мс** | обычный успешный ответ, **8 105 мс** |

Почему так — в коде:

```java
// HttpClientTInvestApiClient: таймаут запроса задан в самом запросе
HttpRequest request = HttpRequest.newBuilder()
        .uri(URI.create(properties.getBaseUrl() + "/v1/instruments"))
        .timeout(properties.getRequestTimeout())            // 5 секунд
        .GET()
        .build();

try {
    response = httpClient.send(request, HttpResponse.BodyHandlers.ofString());
} catch (IOException e) {                                    // HttpTimeoutException — тоже IOException
    throw new TInvestApiException("Не удалось выполнить запрос к instruments-service", e);
}
if (response.statusCode() != 200) {
    throw new TInvestApiException("instruments-service вернул неожиданный статус: " + response.statusCode());
}
```

| Что есть | `HttpClient` | `Reactor` |
|---|---|---|
| Преобразование сбоя в `TInvestApiException` | да | да (статус и разбор), для сети — через `failAndClose` |
| Таймаут запроса | да, `requestTimeout` | **нет** — настройка принимается, но не используется |
| Повтор при сбое (`retry`) | нет | нет |
| Размыкатель цепи (`circuit breaker`) | нет | нет |
| Запасной ответ (`fallback`) | нет | нет |

Как это видит пользователь CLI — `UpdateCommand` ловит `TInvestApiException`:

```java
try {
    quotes = client.fetchQuotes();
} catch (TInvestApiException e) {
    System.out.println("Не удалось получить данные от instruments-service: " + e.getMessage());
    return 1;
}
```

Итог: сбой **обнаруживается** (исключение, понятное сообщение), но дальше ничего не делается: команда
просто завершается с ошибкой. Неблокирующая модель `Reactor` отдельной проблемы надёжности не решает —
она вообще про другое.
